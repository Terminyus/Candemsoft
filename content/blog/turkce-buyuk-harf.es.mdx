## ¿Cuáles son las reglas de mayúsculas İ e I en turco?

Las consultas sobre "mayúsculas en turco", "i con punto mayúscula" y "conversión de mayúsculas y minúsculas en turco" abordan un caso límite clásico en software: la ruptura del estándar ASCII.

En español o inglés existe un único par:
* La letra minúscula `i` se convierte en mayúscula `I`.

En turco, las letras con y sin punto son fonemas independientes:
* **Par con punto:** La minúscula `i` corresponde a la **İ mayúscula con punto**.
* **Par sin punto:** La minúscula `ı` corresponde a la **I mayúscula sin punto**.

Cuando el software no distingue el idioma (locale), surgen errores graves:
* `ilişki` se convierte erróneamente en `ILISKI` o `ILIŞKI` en lugar de `İLİŞKİ`.
* `IŞIK` se transforma de manera incorrecta en `isik` o `işık` en vez de `ışık`.
* `istanbul` se convierte en `ISTANBUL`, produciendo una lectura errónea en vez de `İSTANBUL`.
* `DİYARBAKIR` genera cadenas corruptas como `di̇yarbakir` en lugar de `diyarbakır`.

Esta discrepancia invalida índices de búsqueda, corrompe accesos de usuarios y provoca brechas de seguridad críticas.

## Anatomía Unicode: Puntos de Código de las Cuatro Letras

En el estándar Unicode, cada una de estas cuatro letras cuenta con un punto de código único:

| Letra | Definición | Código Unicode | Bytes UTF-8 |
| :--- | :--- | :--- | :--- |
| **İ** | Latin Capital Letter I with Dot Above | `U+0130` | `0xC4 0xB0` |
| **i** | Latin Small Letter I | `U+0069` | `0x69` |
| **I** | Latin Capital Letter I | `U+0049` | `0x49` |
| **ı** | Latin Small Letter Dotless I | `U+0131` | `0xC4 0xB1` |

### La trampa de la normalización: NFC frente a NFD

Unicode admite dos formatos:
1. **NFC (Composición):** La letra `İ` se almacena en un solo punto precompuesto (`U+0130`).
2. **NFD (Descomposición):** La letra `İ` se divide en una `I` mayúscula (`U+0049`) y un punto combinante (`U+0307`).

Aunque visualmente sean idénticas, las comparaciones binarias (`textoA === textoB`) devuelven `false`. Conviene normalizar siempre con `normalize('NFC')` antes de guardar o indexar cadenas en turco.

## Soluciones para Frontend y JavaScript

### 1. ¿Por qué fallan `toUpperCase()` y `toLowerCase()`?

Las funciones tradicionales de JavaScript aplican reglas ASCII universales:

```javascript
// Enfoque defectuoso:
"istanbul".toUpperCase(); // "ISTANBUL" -> Incorrecto
"İSTANBUL".toLowerCase(); // "i̇stanbul" -> Genera U+0069 + U+0307

// Enfoque localizado:
"istanbul".toLocaleUpperCase("tr-TR"); // "İSTANBUL"
"İSTANBUL".toLocaleLowerCase("tr-TR"); // "istanbul"
"IŞIK".toLocaleLowerCase("tr-TR");     // "ışık"
```

### 2. El peligro de CSS `text-transform: uppercase`

La regla `text-transform: uppercase` cede la conversión al navegador, que lee `<html lang="...">`:

* Si la página declara `<html lang="tr">`, los navegadores convierten `istanbul` a `İSTANBUL` correctamente.
* Si falta el atributo de idioma, el navegador recurre al inglés, convirtiendo la palabra en `ISTANBUL`.
* Los lectores de pantalla pueden deletrear el texto transformado por CSS como un acrónimo.

En interfaces críticas es preferible transformar el texto en la lógica de aplicación antes de enviarlo a la vista.

## Expresiones Regulares y Escapes Unicode

Validar texto turco mediante `/[a-zA-Z]/` rechaza nombres válidos con 'ç, ğ, ı, ö, ş, ü, İ, I'.

En JavaScript moderno deben usarse escapes de propiedades Unicode (`\p{L}`) con la bandera `u`:

```javascript
const patronNombreTurco = /^[\p{L}\s]+$/u;
patronNombreTurco.test("İpek Işık"); // true
```

* `\p{L}`: Coincide con cualquier letra en cualquier idioma.
* `\p{Lu}`: Letras mayúsculas (`İ` e `I` incluidas).
* `\p{Ll}`: Letras minúsculas (`i` e `ı` incluidas).

## Backend y Arquitectura Multilingüe: Python, Go, Java y C#

### Python

Los métodos nativos de Python no aplican reglas locales por defecto:

```python
"i".upper() # Devuelve 'I' en lugar de 'İ'
"ı".upper() # Devuelve 'I'
# 'i'.upper() == 'ı'.upper() provoca colisiones no deseadas
```

Utilice mapeo de caracteres o la biblioteca `PyICU` para una conversión adecuada.

### Go (Golang)

El paquete estándar `unicode` de Go proporciona tablas de caracteres específicas:

```go
import (
    "strings"
    "unicode"
)

mayuscula := strings.ToUpperSpecial(unicode.TurkishCase, "ilişki") // "İLİŞKİ"
minuscula := strings.ToLowerSpecial(unicode.TurkishCase, "IŞIK")   // "ışık"
```

### Java

Ejecutar `.toUpperCase()` sin idioma en Java causa el célebre "Problema de la I Turca":

```java
String mayus = "istanbul".toUpperCase(Locale.forLanguageTag("tr-TR")); // "İSTANBUL"
String minus = "IŞIK".toLowerCase(Locale.forLanguageTag("tr-TR"));     // "ışık"
```

### C# (.NET) y el fallo de seguridad de la I Turca

En servidores Windows con configuración regional turca, `"file".ToUpper()` genera `"FİLE"`. Si un filtro compara rutas contra `"FILE"`, la comprobación fallará y dejará pasar accesos no autorizados.

Para protocolos internos utilice siempre `StringComparison.OrdinalIgnoreCase` o `ToUpperInvariant()`. Reserve `new CultureInfo("tr-TR")` para textos mostrados al usuario.

## Cotejamientos de Base de Datos e Indexación

Las consultas en base de datos requieren configuraciones de cotejamiento adecuadas:

1. **MySQL / MariaDB:** Emplee `utf8mb4_turkish_ci`. Esto garantiza que buscar `ışık` encuentre `IŞIK` sin confundirlo con `işık`.
2. **PostgreSQL:** Cree la base de datos con `LC_COLLATE = 'tr_TR.utf8'` o use `COLLATE "tr-TR-x-icu"`.
3. **SQLite:** El cotejamiento `COLLATE NOCASE` solo gestiona caracteres ASCII. Conviene normalizar el texto en la aplicación antes de persistirlo.

## Preguntas Frecuentes

### 1. ¿Cuáles son los códigos Unicode para la İ mayúscula y la ı minúscula en turco?
La **İ** mayúscula con punto tiene el código `U+0130`, y la **ı** minúscula sin punto es `U+0131`. La **I** mayúscula inglesa es `U+0049`, y la **i** minúscula común es `U+0069`.

### 2. ¿Por qué no debe usarse toUpperCase() en cadenas en turco dentro de JavaScript?
La función estándar `toUpperCase()` convierte `"i"` en `"I"` sin punto, transformando `"istanbul"` en `"ISTANBUL"`. Es indispensable usar `toLocaleUpperCase('tr-TR')`.

### 3. ¿Cómo genera una vulnerabilidad de seguridad el "Problema de la I Turca"?
Si un servidor en turco convierte comandos a mayúsculas, `"file"` se transforma en `"FİLE"`. Los filtros que busquen `"FILE"` no coincidirán en memoria binaria, eludiendo la protección.

### 4. ¿Por qué CSS text-transform: uppercase no es fiable en tipografía turca?
Depende del entorno del navegador y del atributo `<html lang>`. Si falta la etiqueta, las letras se alteran y los lectores de pantalla pueden deletrear el texto como siglas.

### 5. ¿Cómo configurar bases de datos para búsquedas insensibles a mayúsculas en turco?
En MySQL o MariaDB utilice `utf8mb4_turkish_ci`. En PostgreSQL configure el cotejamiento ICU `tr-TR-x-icu`. En SQLite normalice los textos en el código antes de la consulta.
